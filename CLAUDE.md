# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Artel is a native macOS 26+ (arm64) SwiftUI app for running several coding-agent sessions (Claude Code, Kimi Code) in parallel, with a lightweight task board: a task is a prompt with attachments that can be dropped into a session, optionally in its own git worktree. Product spec: `docs/SPEC.md`; user-facing overview and hotkeys: `README.md`. The UI, docs, prompts and comments are in English (English only, no localization tables). Parsing of user data stays language-neutral; the few places that still accept legacy Russian input (a «Спеки» section in CLAUDE.md, the old default tab name) say so in a comment.

## Build & test

Only Command Line Tools are installed — no Xcode. Everything goes through SwiftPM and the scripts:

```sh
scripts/build-app.sh             # release → build/Artel.app (builds Artel, artel-hook, bundles tmux and the preview's JS, ad-hoc signs)
scripts/build-app.sh debug       # debug build
scripts/build-app.sh --install   # also copy to /Applications (needed for running sessions to pick up a new artel-hook)
scripts/test.sh                  # unit tests (swift-testing); wraps `swift test` with CLT framework paths
scripts/test.sh --filter HistoryTests          # one suite / file
scripts/test.sh --filter "TaskFileFormat/roundTrip"   # one test
scripts/release.sh 0.2.0 [--notes notes.md] [--dry-run]   # GitHub release + Sparkle appcast; one-time setup in its header
scripts/build-excalidraw-editor.sh   # optional Excalidraw download (needs Bun) → build/excalidraw/*.zip + sha256
```

Use `scripts/test.sh`, not bare `swift test` — under CLT the latter cannot find the Testing framework. Tests cover `ArtelCore` only; the app target has no tests.

CLT constraints that matter when adding code or dependencies:
- SwiftUI/Observation macros that need Xcode's plugin are unavailable: no `@Entry`, no `#Preview`. Dependencies that use them (e.g. Textual) won't build — that is why short read-only markdown (history entries, archive prompts) uses MarkdownUI; documents use the WKWebView preview.
- The `Artel` target compiles in Swift 5 language mode; `ArtelCore`/`ArtelHook` use Swift 6. In Swift 5 mode prefer `NSRegularExpression` over Swift `Regex` literals (lookbehind / bare `/.../` literals don't work).

## Architecture

Three SwiftPM targets:
- `ArtelCore` — all testable logic: models (`Models.swift`, `TaskModel.swift`), tmux control, the agent launch command (`CodingAgent.swift`), hook event log and the session status state machine (`SessionActivity`/`SessionStatus.applying`), task storage, git worktrees and diff, prompt templates, project docs discovery, the documentation site (`DocsSite.swift`: Docusaurus-style tree, frontmatter; `DocsLinks.swift`: link rewriting on move, search, link completion, agent prompts), usage limits.
- `ArtelHook` (`artel-hook`) — hook handler for Claude Code and Kimi Code sessions. Must always exit 0 and print nothing; appends to `events/<session>.jsonl` and pings the app over a unix socket.
- `Artel` — the SwiftUI app. `AppModel` (`@Observable`, split into `AppModel.swift`, `+Tasks`, `+NoTasks`, `+Workflow`, `+Docs`) owns all state; views in `Sources/Artel/Views`.

The main window is IDE-style (`IslandsLayout.swift`): the window hides the system title bar and has no bar of its own. The tool panel's header (`PanelHeader`) sits in the top row next to the traffic lights, at the system titlebar's height so they stay centred; the content island goes up to the window's top edge (below the traffic lights while the panel is hidden). On the left, a rail of section icons (clicking the open section hides its tool panel; also Add Project and New Task), then the tool panel and the content as rounded "islands". Each section's actions live in its panel (Tasks: search and filters; Projects: Add Folder, Files, editor, Finder, settings). Empty canvas (`WindowDragArea`) moves the window. Sections, in rail order: Workspace (session grid; its panel is the Agent Sessions tree: projects → sessions, open tasks, archives), Projects (documentation, `ProjectsView.swift`; its panel is `ProjectsList`), Tasks (board; its panel is the tasks tree: waiting sessions, then projects → tasks under the board's search and filters, sessions without a task and archives). Both trees are `ProjectTree` (`ProjectTree.swift`, JetBrains-style: collapsible projects and groups, ↑/↓/⏎). Markdown is always shown rendered (`MarkdownWebView`: WKWebView loading `Resources/DocsRenderer` through the `artel-res://local/{app,root}/` scheme; JS libraries come from `scripts/fetch-docs-web.sh` into `build/vendor/docs-web`, pinned by sha256, and are copied into the bundle by `build-app.sh`; a SwiftPM-only run reads them from the repo). "Edit" opens the source editor (`MarkdownTextEditor`: NSTextView, regex highlighting, its own link-completion popup) on a draft in `AppModel.markdownDrafts` (keyed by `DocumentKey`); saving is explicit, unsaved documents show a dot and are asked about on quit. The documentation folder of a project is `Project.docsFolder` in `state.json` (never written into the project), else `DocsSite.detect`. "Ask the agent" starts a no-task session in the project checkout with `DocsPrompt`. Excalidraw drawings use the built-in rough.js renderer (`Resources/DocsRenderer/excalidraw.js`) unless the operator installed the Excalidraw download (`ExcalidrawAddon`): React + `@excalidraw/excalidraw` bundled from `Resources/ExcalidrawEditor/` by `scripts/build-excalidraw-editor.sh` (needs Bun; `bun.lock` is committed), published as the GitHub release `excalidraw-<version>` (with `--latest=false`: the Sparkle feed is the *latest* release's appcast) and pinned by `ExcalidrawAddon.version`/`sha256` (update both after a rebuild, then publish that exact zip). It is unpacked into `AppPaths.root/renderers/` and served as `artel-res://local/ext/excalidraw/`; the preview imports `sceneToSvg`, `ExcalidrawEditorView` (`excalidraw-editor.html`) mounts the editor. The editor's web view routes Excalidraw's ⌘-shortcuts to the page with a local key monitor (the app menu would eat them). For development, `ARTEL_EXCALIDRAW_BUNDLE=<zip>` installs a local build without the hash check.

Session flow: the app starts an agent (`claude --settings <hooks> --session-id <id>` for Claude Code, `kimi` with hooks from `~/.kimi-code/config.toml` for Kimi Code) inside a private tmux server (`tmux -L artel`) and shows it via SwiftTerm. Hooks → `artel-hook` → `events/*.jsonl` is the source of truth for session status (replayed on launch); the socket is only for live updates. Sessions survive app quit; a missing tmux session is revived with the agent's resume command (`claude --resume` / `kimi --session`). Agents implement `CodingAgent` (`ClaudeCodeAgent`, `KimiCodeAgent`, registry `CodingAgents`); per-agent default models live in `AppSettings.defaultModels`, the default agent in `defaultAgentID`.

Tasks are files, not app state: `<project>/.artel/tasks/<ID>-<slug>/` holds `task.md` (frontmatter + body = prompt), `history.jsonl` (append-only timeline), `attachments/` and `logs/`. Statuses are `new` → `in-progress` (set on launch) → `done` (operator only); there is no plan/review/testing workflow, no comments and no MCP server — the prompt is the first message and the rest happens in the terminal. Old task.md files are tolerated: `TaskStatus(stored:)` maps legacy stages to `in-progress` and `cancelled` to `done`, obsolete frontmatter keys are dropped on rewrite. The app reloads tasks by fingerprint, so external edits are expected. A task runs in the project checkout unless the launch dialog asks for a worktree: then it gets `~/.artel/worktrees/<project>/<ID>` on branch `artel/<ID>-<slug>`, with `.artel/` excluded via sparse-checkout, and keeps it for later launches. Artel never merges: closing a task can remove the worktree and an already merged branch. The agent reaches the task folder through `--add-dir`. A project doesn't have to be a git repository or have CLAUDE.md: `ProjectValidator` only makes the add-project sheet offer `git init` and a CLAUDE.md template. Without git (`Project.isGitRepository`, checked live) the worktree option, base branch and committing `.artel/` are hidden and tasks run in the project folder.

Sessions without a task are archived by `NoTaskStore` in `<project>/.artel/no-task/<session-id>/`, titled from the first prompt and expired seven days after their last update on every read/write. Promotion moves the whole archive into `tasks/` as a numbered `done` task with its history and logs. `no-task/` and `tasks/*/logs/` are never committed.

App data: `~/Library/Application Support/Artel/` (`state.json`, `events/`, generated `claude-settings.json`, `tmux.conf`, `bin/artel-hook`).

Self-update: Sparkle (SwiftPM binary framework, copied into `Contents/Frameworks` by `build-app.sh`). `SUFeedURL` is `appcast.xml` of the latest GitHub release of `UxiT/artel`. The updater checks at every launch (`checkForUpdatesInBackground` right after start) and daily while running; a found update opens Sparkle's own dialog (English, the app's `en` development region). `scripts/release.sh` sets `CFBundleShortVersionString` and `CFBundleVersion` (kept equal), builds, zips, signs the zip with the EdDSA key from the Keychain (`generate_appcast`), packs a DMG for first installs (app + `/Applications` link; Sparkle updates use the zip) and publishes all three with `gh`. The updater (`Updater.swift`) stays off while `SUPublicEDKey` is empty, outside an .app bundle and with `ARTEL_HOME` (unless `ARTEL_UPDATE_FEED` is set).

Artel used to be called Aide. `LegacyAide` (core) and `LegacyMigration` (app) upgrade an Aide install in place: they quit Aide, move `Application Support/Aide` (leaving a symlink for running sessions), keep using the `aide` tmux server while it is up and rename its sessions, read a project's `.aide/` task folder in place (`TaskStore.dirName`), accept old JSON keys, `AIDE_*` variables in the hook and Kimi's old config block. Keep the old names inside that layer; don't rename them elsewhere.

## Running / verifying the UI

There is no way to drive the UI by gestures from outside, so verification uses built-in debug hooks (see `Sources/Artel/DebugSnapshot.swift` for the step list):
- `ARTEL_HOME=<tmp dir>` — isolated data dir (use this for a second/dev instance; don't touch the user's real state). Also set `KIMI_CODE_HOME=<tmp dir>`: otherwise the instance rewrites the hooks block in the real `~/.kimi-code/config.toml` to point at its own hook binary.
- `ARTEL_WORKTREES=<dir>` — worktree root override.
- `ARTEL_UPDATE_FEED=<appcast URL>` — turns the updater on in an `ARTEL_HOME` instance and points it at that feed, to see the update dialog. Sparkle only takes http(s): serve a test appcast with `python3 -m http.server --bind 127.0.0.1`. Run a copy of the app with another `CFBundleIdentifier`, or Sparkle writes its state into the real app's defaults.
- `ARTEL_SNAPSHOT=/path.png` — renders the main window (or the open sheet) to PNG every 3 s, no screen-recording permission needed. Vibrancy/toolbar glass renders as blank blobs — a known artifact, not a bug.
- `ARTEL_DEBUG_SCRIPT='[{"section":"projects"},{"project":0},{"doc":"docs/index.md"},{"edit":true},{"snapshot":"/path.png"}]'` — scripted actions after start-up (select, launch, setStatus, done, edit, files, docsSearch, webText …); progress goes to `$ARTEL_DEBUG_LOG`. Snapshots paint WKWebView content over its frame; `{"webText":true}` logs what the previews rendered. Glass buttons (`.glassProminent`) in a pane blank that pane in snapshots — an artifact.

## Constraints

- Subscription limits are read from the existing Claude Code (Keychain) and Kimi Code (`~/.kimi-code/credentials/`) logins — read only, never write them. Never print or log OAuth tokens. The User-Agent stays generic (`Artel/<version>`); never put the user's email in requests.
- Committing `.artel/` in user projects happens only on explicit operator action.
- Artel is GPL-3.0 for now, but may go closed-source, so every dependency stays permissive (MIT, BSD, ISC, Apache-2.0): no GPL, LGPL or AGPL code, statically linked or bundled. `build-app.sh` copies the license of every package pinned in `Package.resolved` into `Contents/Resources/Licenses/`; a bundled binary or script that doesn't come from SwiftPM (tmux, libevent, the preview's JS libraries) needs its license copied there too (`build/vendor/licenses/`).
